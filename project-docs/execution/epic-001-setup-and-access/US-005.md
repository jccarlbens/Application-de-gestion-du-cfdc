# US-005 : Double authentification par email

**Statut :** 🔲 À faire
**Milestone :** Epic 1 — Mise en place et accès
**GitHub Issue :** [#5](https://github.com/jccarlbens/Application-de-gestion-du-cfdc/issues/5)
**Dépend de :** US-004

---

## En tant que coordonnateur
Je veux recevoir un code par email après mon mot de passe
Afin que mon compte reste protégé même si mon mot de passe est découvert

## Contexte
Étape 2 du flux de `SOLUTION_DESIGN.md` §7. L'email est le canal par défaut et le seul exigé pour la mise en service (`PLAN.md`, MoSCoW). En développement et sur le serveur de test, les emails partent vers Mailpit (affinage de l'Epic 1, Q3). Workstream : WS-01.

Règles : code valable **5 minutes**, à **usage unique** ; en dernier recours, l'administrateur donne un **code de secours** (`NFR.md` § Fiabilité).

## Critères d'acceptation
- [ ] Après un mot de passe correct, un code est envoyé à l'email de l'utilisateur, et la session ne s'ouvre qu'avec ce code.
- [ ] Le code expire après 5 minutes et ne sert qu'une fois.
- [ ] Un code faux est refusé ; les échecs de code comptent dans les 5 échecs qui bloquent le compte.
- [ ] L'administrateur peut générer un code de secours pour un utilisateur ; ce code est journalisé.
- [ ] Le serveur d'email se configure par variables d'environnement (SMTP), sans rien de codé en dur.

## Hors périmètre

## Tâches
*Provisoires : remplacées par le plan d'implémentation validé, à l'étape « planifier ».*
