# US-004 : Connexion et session

**Statut :** ✅ Terminé
**Milestone :** Epic 1 — Mise en place et accès
**GitHub Issue :** [#4](https://github.com/jccarlbens/Application-de-gestion-du-cfdc/issues/4)
**Dépend de :** US-002

---

## En tant que secrétaire
Je veux me connecter avec mon numéro de badge et mon mot de passe
Afin d'accéder à l'application en sécurité, sans que quelqu'un d'autre puisse utiliser mon compte

## Contexte
Flux de `SOLUTION_DESIGN.md` §7 et ADR 5 ; règles de `NFR.md` § Sécurité et `PRD.md` §9. Le rôle « secrétaire » est un exemple : tout utilisateur se connecte de la même façon. Workstream : WS-01.

Règles : mot de passe d'au moins 8 caractères dont un chiffre ; blocage après **5 échecs**, déblocage par l'administrateur seulement ; session côté serveur, cookie `HttpOnly`, `Secure`, `SameSite`, expirant après **15 minutes** sans activité ; un compte désactivé ou bloqué perd ses sessions immédiatement.

Ne pas supposer : la double authentification vient en US-005 ; cette user story ouvre la session directement après le mot de passe, et US-005 insérera l'étape du code.

**Affiné le 2026-11-17, avant construction :**
- **Ce que la lecture du code a changé.**
  - `get_current_actor` (`app/api/v1/security.py`) répond toujours « non connecté » : c'est le seul point à remplacer pour que les routes de US-002 et US-003 deviennent utilisables.
  - Aucune table de sessions ni compteur d'échecs n'existe.
  - Le journal de US-003 impose que chaque nouvelle table soit journalisée ou exemptée ; et un compteur d'échecs dans `users` ajouterait une entrée au journal du compte à chaque mauvais mot de passe, avec un « auteur » qui n'est pas encore connecté.
  - Le serveur de test est public : le blocage par compte ne protège pas contre l'essai de nombreux badges différents.
- **Tentatives** (décision 1A) : une table **`login_attempts`** (heure, badge saisi, compte s'il existe, réussite ou échec, motif) ; les échecs s'y comptent ; le compte n'est modifié, donc journalisé, qu'au moment où il est **bloqué**.
- **Sessions** (décision 2) : une table **`auth_sessions`**, exemptée du journal, qui ne garde que l'empreinte du jeton. Le préfixe `auth_` évite la confusion avec les sessions de formation.
- **Cookie** (décision 3) : `HttpOnly`, `Secure`, **`SameSite=Strict`** ; l'interface et l'API étant à la même adresse, cela suffit contre les attaques venues d'autres sites.
- **Déblocage** (décision 4A) : une route pour l'administrateur **et** une commande `unblock-user --badge …`, en attendant l'écran de US-009.
- **Pas de limite par adresse IP** (décision 5B) : le blocage par compte suffit pour la V1. Risque accepté sur le serveur de test, public mais sans données réelles.
- **5 échecs consécutifs** (décision 6) : une connexion réussie ou un déblocage remettent le compte à zéro.
- **Après la connexion** (décision 7) : une page d'accueil « Connecté : Prénom Nom (badge) » avec « Se déconnecter », en attendant les menus de US-007 ; une session expirée ramène à l'écran de connexion avec « Votre session a expiré, reconnectez-vous. »
- **Qui construit** (décision 8) : l'agent, pour l'administrateur informatique.
- **Vocabulaire** (consigne du 2026-11-17) : on écrit **« numéro de badge »** partout, dans les écrans et les messages.

## Critères d'acceptation
- [ ] Un écran de connexion demande le **numéro de badge** et le mot de passe, en français.
- [ ] Des identifiants corrects ouvrent une session ; des identifiants faux affichent « Numéro de badge ou mot de passe incorrect. », sans dire lequel des deux est faux. Un compte bloqué ou désactivé n'est signalé comme tel qu'à qui a donné le bon mot de passe.
- [ ] Au 5e échec consécutif, le compte est bloqué ; seul l'administrateur peut le débloquer, par une route ou par la commande `unblock-user`. Une connexion réussie ou un déblocage remettent le compte à zéro.
- [ ] Un compte désactivé ne peut pas se connecter.
- [ ] La session expire après 15 minutes sans activité ; chaque action la prolonge.
- [ ] Après la connexion, une page affiche « Connecté : Prénom Nom (badge) » ; le bouton « Se déconnecter » ferme la session.
- [ ] Une session expirée ramène à l'écran de connexion avec « Votre session a expiré, reconnectez-vous. »
- [ ] Les routes de US-002 et US-003 fonctionnent avec la session de l'utilisateur connecté.
- [ ] Bloquer ou désactiver un compte ferme ses sessions ouvertes.
- [ ] Le mot de passe est refusé s'il fait moins de 8 caractères ou n'a pas de chiffre.
- [ ] Les connexions réussies et échouées sont journalisées, sans le mot de passe (déplacé de US-003 le 2026-11-16 ; `NFR.md` § Observabilité).

## Hors périmètre
- La double authentification (US-005, US-008).
- Le mot de passe oublié (US-006).
- Les menus selon le rôle (US-007).
