## En tant que direction du CFDC

Afin que chacun travaille simplement, sans accès à ce qui ne le concerne pas

## Contexte
Tableau des droits de `PRD.md` §5 ; « le serveur décide des droits » (`AGENTS.md`). Workstream : WS-01.

Cette user story pose le **mécanisme** : un contrôle côté serveur réutilisable, et une interface qui montre l'accueil et les menus selon le ou les rôles. Les droits précis de chaque fiche métier se brancheront sur ce mécanisme dans les Epics suivants.

**Affiné le 2026-11-17, avant construction :**
- **Ce que la lecture du code a changé.**
  - Les droits sont déjà vérifiés, mais **dans la BLL**, fonction par fonction (`bll_user.py`, `bll_history.py`) ; les routes, elles, ne déclarent rien : un test ne peut pas voir une route qui aurait oublié son contrôle.
  - Certaines règles sont plus fines qu'une liste de rôles (le coordonnateur crée des comptes, mais jamais d'administrateur ; le dernier administrateur est protégé).
  - Quatre routes sont **ouvertes exprès** : `/health`, `/auth/login`, `/auth/logout`, `/password/setup`.
  - Aucun écran métier n'existe encore : les menus ne mènent nulle part avant US-009 et les Epics 2 à 6.
- **Deux niveaux de droits** (décision 1A) : chaque route déclare les rôles autorisés, et refuse les autres en `403` avant tout traitement ; les règles fines restent dans la BLL ; les routes ouvertes sont déclarées **publiques** ; un test échoue si une route n'est ni publique ni protégée.
- **Menus** (décision 2A) : la liste complète des menus est définie dès maintenant à partir du tableau des droits (`PRD.md` §5) ; chaque rôle ne voit que les siens ; un menu dont l'écran n'existe pas encore mène à une page « Bientôt disponible ».
- **Forme** (décision 3A) : une barre verticale à gauche sur ordinateur ; sur téléphone, un bouton « Menu » qui l'ouvre.
- **Accueil** (décision 4) : « Connecté : Prénom Nom (badge) », les rôles en français, et des raccourcis vers les menus de la personne.
- **Noms des rôles à l'écran** (décision 5) : « Secrétaire », « Coordonnateur », « Chef de service du CFDC », « Formateur », « Administrateur informatique », « Direction du CFDC ».

## Critères d'acceptation
- [ ] Chaque route de l'API déclare les rôles autorisés ; une requête d'un rôle non autorisé reçoit un refus `403`, même si l'interface a été contournée.
- [ ] Un test vérifie que chaque route de l'API est soit déclarée publique, soit protégée par une liste de rôles.
- [ ] Après la connexion, l'utilisateur arrive sur un accueil qui ne montre que les menus de ses rôles ; une personne à plusieurs rôles voit l'union de leurs menus.
- [ ] L'interface est en bleu et blanc, en français, et s'utilise sur Chrome et Edge et sur un téléphone connecté au réseau interne.
