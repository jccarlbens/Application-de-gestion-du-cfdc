# US-008 : Double authentification par SMS

**Statut :** 🔲 À faire
**Milestone :** Epic 1 — Mise en place et accès
**GitHub Issue :** [#8](https://github.com/jccarlbens/Application-de-gestion-du-cfdc/issues/8)
**Dépend de :** US-005

---

## En tant que secrétaire
Je veux pouvoir recevoir mon code de connexion par SMS plutôt que par email
Afin de me connecter même quand l'email ne passe pas

## Contexte
**Priorité Should** (`PLAN.md`) : l'email seul suffit pour la mise en service. Dépend des fournisseurs et du budget, encore ouverts (`SOLUTION_DESIGN.md` §15, Q2). Fournisseurs : **Digicel** et **Natcom**, selon le numéro (`NFR.md` § Dépendances), derrière une interface commune (ADR 4). Workstream : WS-01.

## Critères d'acceptation
- [ ] L'utilisateur choisit son canal (email ou SMS) ; l'email reste le choix par défaut.
- [ ] Le SMS part par Digicel ou Natcom selon le numéro de téléphone.
- [ ] Si le canal choisi échoue, le code part automatiquement par l'autre canal.
- [ ] Les fournisseurs se configurent par variables d'environnement ; aucun n'est codé en dur.

## Hors périmètre
- Toute autre notification par SMS (`PRD.md` §13).

## Tâches
*Provisoires : remplacées par le plan d'implémentation validé, à l'étape « planifier ».*
- [ ] Adaptateurs Digicel et Natcom derrière une interface commune.
- [ ] Choix du canal dans le profil.
- [ ] Bascule automatique.
- [ ] Tests avec un faux fournisseur.

## Définition du terminé
- [ ] Sur le serveur de test, avec un faux fournisseur : recevoir le code par SMS, puis simuler une panne et le recevoir par email.
- [ ] Les cinq points de la définition du « terminé » de `PROJECT_WORKFLOW.md` sont remplis.
- [ ] L'administrateur informatique valide → la user story passe à Terminé.
