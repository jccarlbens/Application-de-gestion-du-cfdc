# US-012 : Documents de cours

**Statut :** ✅ Terminé
**Milestone :** Epic 2 — Formations et modules
**GitHub Issue :** [#20](https://github.com/jccarlbens/Application-de-gestion-du-cfdc/issues/20)

## En tant qu'administrateur informatique
Je veux déposer les documents de cours de chaque module
Afin que les formateurs disposent de leurs supports dans l'application

## Contexte
Affinage : `epic-002-refinement.md`. Workstream : WS-02. Fiche **Document de cours** de `SOLUTION_DESIGN.md` §6 ; fichiers sur le disque du serveur, dans le volume `documents` (ADR 4, `docker-compose.yml`).

Décisions de l'affinage qui s'appliquent ici :
- **Q6 :** le **formateur du module** et l'**administrateur** ouvrent les documents ; le coordonnateur et les chefs de service voient la **liste** des documents d'un module, sans les ouvrir.
- **Q7 :** **25 Mo** au plus ; PDF, PowerPoint (`.ppt`, `.pptx`), Word (`.doc`, `.docx`), vérifiés par l'extension **et** par le contenu du fichier.
- **Q8 :** sur le serveur de test (Render gratuit), les fichiers sont perdus à chaque redémarrage : c'est accepté.
- **Q9 :** remplacer un document, c'est déposer une nouvelle version ; l'ancienne reste, marquée « remplacée », et seul l'administrateur peut encore l'ouvrir. Rien ne s'efface.

Le menu « Documents de cours » (administrateur seul) existe depuis US-007.

**Affinage commencé le 2026-11-20 : ce que la lecture du code a changé.**
- **Nginx refuserait un fichier de plus de 1 Mo.** `frontend/nginx/default.conf.template` ne fixe pas `client_max_body_size`, dont la valeur par défaut est 1 Mo. Un document de 25 Mo recevrait `413`, avec un message générique en anglais. Il faut relever la limite dans Nginx, au-dessus de 25 Mo, et la vérifier aussi dans le backend.
- **Le backend ne sait pas encore recevoir un fichier.** FastAPI a besoin de la bibliothèque `python-multipart`, absente de `backend/pyproject.toml`.
- **Le volume `documents` est monté** (`docker-compose.yml`, `/data/documents`), mais aucun réglage ne le nomme au backend : il faut une variable `DOCUMENTS_DIR`. Sur Render, le dossier est dans le conteneur et se vide à chaque redémarrage (Q8, accepté).
- **Vérifier le contenu d'un fichier, format par format :**
  - **PDF** : le fichier commence par `%PDF` ;
  - **`.docx` et `.pptx`** : ce sont des archives ZIP, qu'on reconnaît à leur dossier `word/` ou `ppt/` ;
  - **anciens `.doc` et `.ppt`** : ils partagent la même en-tête OLE2. On peut vérifier que c'est un document Office ancien, mais pas distinguer simplement un Word d'un PowerPoint.
- **L'historique est commun** : un document peut s'inscrire dans l'historique de sa formation, comme les modules (US-011, décision 5A).
- **Un lien de téléchargement suffit** : le cookie de session part avec un simple lien vers l'API, puisque l'interface et l'API sont à la même adresse (ADR 5).

**Décisions du 2026-11-20 :**
- **Dépôt** (décision 1A) : l'administrateur dépose un document **dans un module, sur la fiche de la formation**. Le menu « Documents de cours » liste tous les documents, par formation puis par module, avec un lien vers chaque formation.
- **Liste visible** (décision 2) : tous ceux qui voient la fiche (secrétaire, coordonnateur, chef de service, administrateur, direction) voient la liste des documents d'un module : nom, date, déposé par. Ceci élargit Q6, qui ne citait que le coordonnateur et les chefs de service. **Seuls le formateur du module et l'administrateur ouvrent un document.**
- **Nom affiché** (décision 3A) : le nom du fichier déposé, qui est aussi son nom au téléchargement.
- **Remplacer** (décision 4) : un bouton « Remplacer » sur chaque document en vigueur ; l'ancienne version passe dans « Versions remplacées », que seul l'administrateur ouvre.
- **Historique** (décision 5A) : les dépôts et remplacements s'inscrivent dans l'historique de la formation.
- **Anciens `.doc` et `.ppt`** (décision 6) : acceptés si leur contenu est un document Office ancien (en-tête OLE2), sans distinguer Word et PowerPoint.
- **Accès du formateur** (décision 7) : il suit le formateur **actuel** du module ; l'ancien formateur ne l'a plus.
- **Qui construit** (décision 8) : l'agent, pour l'administrateur informatique.

## Critères d'acceptation
- [ ] Sur la fiche d'une formation, l'administrateur dépose un document dans un module ; seuls les PDF, Word (`.doc`, `.docx`) et PowerPoint (`.ppt`, `.pptx`) de **25 Mo au plus** sont acceptés ; un autre format ou un fichier trop gros est refusé avec un message clair en français.
- [ ] Un fichier dont le contenu ne correspond pas à son extension est refusé.
- [ ] Un document garde : module, nom du fichier, taille, déposé par, date ; le dépôt est journalisé dans l'historique de la formation.
- [ ] L'administrateur remplace un document par une nouvelle version ; l'ancienne passe dans « Versions remplacées » ; rien ne s'efface.
- [ ] Le téléchargement est vérifié par le serveur : le formateur **actuel** du module et l'administrateur ouvrent les documents en vigueur ; seul l'administrateur ouvre une version remplacée ; tout autre rôle reçoit `403`.
- [ ] Tous ceux qui voient la fiche d'une formation voient la liste des documents de chaque module (nom, date, déposé par), sans pouvoir les ouvrir.
- [ ] Le menu « Documents de cours » (administrateur) liste tous les documents, par formation puis par module, avec un lien vers chaque formation.
- [ ] Un fichier de 25 Mo passe par Nginx (la limite par défaut, 1 Mo, est relevée).

## Notes de réalisation

*2026-11-20, construction sur la branche `claude/gallant-newton-x8fyao`.*
- **Table `course_documents`** : migration `f17fc41a3361`, vérifiée dans les deux sens. Le nom sur le disque est aléatoire, jamais celui envoyé par le navigateur ; seul le dernier élément du nom est gardé (`C:\…\Cours.pdf` ou `../../Cours.pdf` deviennent `Cours.pdf`).
- **Pas de fichier orphelin :** le fichier est écrit dans un temporaire, renommé, puis la fiche est enregistrée ; si la fiche échoue, le fichier est effacé (test d'intégration).
- **Nginx refusait tout envoi de plus de 1 Mo** (constat de l'affinage) : `client_max_body_size 26m`, et une réponse `413` en JSON français, « Le fichier dépasse 25 Mo. », que l'interface affiche. Vérifié avec la configuration du projet, Nginx lancé seul (Docker ne fonctionne pas sur la machine de travail) : un PDF de 20 Mo passe, un de 27 Mo est refusé par Nginx, un faux PDF par le backend.
- **Défaut du journal trouvé par le parcours, et corrigé pour toutes les tables :** une entrée de création gardait une clé étrangère **vide** quand la fiche était reliée par un objet plutôt que par son identifiant. C'était `module_id` des documents ; et, depuis US-003, `user_id` des rôles créés avec leur compte (ils étaient pourtant rangés sous le bon compte). Le journal photographie la ligne avant que SQLAlchemy ne remplisse ces clés ; `_fill_foreign_keys` (`app/dal/dal_audit.py`) les recopie d'abord. Deux tests le vérifient, vus échouer sans la correction. Les entrées déjà écrites restent telles quelles : le journal ne se modifie pas.
- **Ouvrir un document :** la route laisse passer le formateur et l'administrateur ; la BLL vérifie que c'est le formateur **actuel** du module, et réserve les versions remplacées à l'administrateur. Un fichier perdu (serveur de test redémarré) répond `404` « Le fichier de ce document est introuvable sur le serveur. ».
- **Téléchargement :** un simple lien vers l'API ; le nom d'origine, accents compris, est encodé par Starlette (`filename*=utf-8''…`).
- **Tests :** 346 au backend (sur la base locale, et deux fois sur une base vide migrée de zéro), 119 au frontend ; Steiger, oxlint et le build passent.
